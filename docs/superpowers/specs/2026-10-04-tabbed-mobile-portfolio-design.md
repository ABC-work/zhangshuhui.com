# 分段式移动作品集设计

## 目标

将个人网站从连续纵向阅读的长作品集，调整为招聘者可以主动选择信息的产品浏览器。移动端优先解决两个问题：整屏黑白切换造成的品牌割裂，以及必须持续向下滑动才能找到关键信息。

## 设计原则

1. 全站使用统一暖白背景，黑色只用于文字、边框和局部产品框架。
2. 电蓝作为唯一主强调色，不再使用整屏黑色主题。
3. 首页负责选择项目，不负责完整讲述旗舰项目。
4. 项目页按用户问题组织，而不是按项目时间线组织。
5. 标签切换替代超长顺序阅读，同时保留可分享的深链接。
6. 默认内容在一个手机首屏内建立项目、问题与结果的基本认识。

## 首页信息架构

首页控制在约三至四个 390px 手机屏幕内：

1. 定位：姓名、岗位和“把复杂业务做成产品”的核心主张。
2. 项目选择：Collab、Creator Intelligence、Airacle 三张统一样式的项目入口。
3. 可信结果：只保留三个最强证据，不在首页展开统计解释。
4. 联系：邮箱与所在地。

首页移除 Collab 的完整决策、截图序列与长结果段落。

## 项目页信息架构

每个项目使用相同的吸附式分段导航：

- `概览`：问题、个人角色、核心结果和一张主证据图。
- `决策`：二至三个真正体现产品判断的取舍。
- `产品`：经过裁切、标注的真实界面，或明确标识为流程的非界面视觉。
- `结果`：数据、样本边界、尚未证明的内容与复盘。

默认只显示概览。点击标签后切换面板，不要求用户继续向下寻找；标签保持可见。每个面板控制在约两个手机屏幕内。

## URL 与状态

- 标签分别对应 `#overview`、`#decisions`、`#product`、`#outcome`。
- 首次加载根据 URL hash 激活面板；无 hash 时显示概览。
- 点击标签更新 hash，并使用浏览器历史记录。
- 浏览器前进、后退时恢复对应标签。
- JavaScript 不可用时，四个面板按正常文档顺序全部显示，内容仍可访问。

## 视觉与响应式

- 背景统一为暖白 `#f5f4ef`，正文为近黑色，强调色为电蓝。
- 项目页不再通过 `body` 类切换黑色或蓝色主题。
- 移动端标签横向排列在一行；文字短且点击区域不小于 44px。
- 桌面端使用左侧吸附标签与右侧内容的双栏布局，避免把移动端简单拉宽。
- 当前标签同时使用颜色、字重和下划线表达，不能只依赖颜色。
- 面板切换只使用轻微透明度变化，并尊重 `prefers-reduced-motion`。

## 组件边界

### 项目卡

负责项目选择，只包含项目类型、名称、一句价值、核心证据和视觉缩略图。

### 分段导航

负责展示当前信息类别、切换面板和同步 URL，不承担页面级导航。

### 项目面板

每个面板通过 `data-panel` 与对应标签关联。隐藏状态使用 `hidden` 属性，确保语义和辅助技术行为一致。

### 证据图

使用统一的浏览器框架、裁切比例和说明文字。Creator Intelligence 的工作流必须明确是流程图，不伪装成真实界面。

## 可访问性

- 分段导航使用 `role="tablist"`、`role="tab"` 和 `role="tabpanel"`。
- 标签实现 `aria-selected`、`aria-controls`、键盘左右方向键和 Home/End 切换。
- 切换后焦点保持在标签，不强制跳入内容。
- 无障碍模式与无 JavaScript 模式仍可读取全部项目内容。

## 验收标准

1. 首页不再连续展示 Collab 的完整案例，移动端长度约三至四屏。
2. 三个项目页均使用相同的四段导航和统一暖白视觉。
3. 任意项目首屏包含项目名称、问题、核心结果与分段导航。
4. 点击四个标签时只有对应面板可见，URL hash 正确更新。
5. 直接访问任意 hash、刷新、前进和后退均恢复正确面板。
6. 键盘可使用 Tab、方向键、Home 和 End 完成切换。
7. 禁用 JavaScript 后四个面板全部可读。
8. 390px 宽度无横向页面溢出，标签点击区域不小于 44px。
9. 页面不存在整屏纯黑背景或项目级主题跳变。
10. 桌面、390px 手机和公网部署分别完成视觉检查。
