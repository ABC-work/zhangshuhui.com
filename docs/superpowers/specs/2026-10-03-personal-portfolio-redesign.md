# zhangshuhui.com 个人作品集改版设计

## 1. 目标

将现有的泛 AI 个人主页重构为面向招聘者的证据型产品经理作品集。招聘者应在 30 秒内理解：

- 张树蕙是有 2 年 AI 应用产品经验的产品经理；
- 能将复杂的人工业务流程抽象为可落地的产品规则；
- 已推动真实产品从需求、PRD、交互、研发到上线；
- 能合理使用大模型与 AI 工具，并理解规则、人工复核和异常流程的价值；
- 有可验证的项目截图、业务结果、决策与复盘，而非只有技能标签。

## 2. 受众与转化目标

主要受众是北京中小型 AI 应用、B 端 SaaS 及工具产品团队的 HR、产品负责人与创始人。

核心转化路径：

1. 理解个人定位；
2. 看到可验证的结果；
3. 打开一个深度案例；
4. 确认候选人的角色、决策与能力边界；
5. 下载简历或通过邮箱联系。

## 3. 内容原则

- 只使用已核验的简历与对话事实；
- 删除“算法工程师”、AI 专利、Knockit、App Store Creator 等未核实内容；
- 不发布客户敏感数据、联系方式、报价、密钥、私有代码或未授权案例；
- 项目指标必须附带口径，不将局部样本包装成全量结论；
- 每个案例重点展示产品判断、取舍、结果和复盘，不做功能清单。

## 4. 站点结构

### 4.1 首页

1. 固定导航：个人标识、项目、方法、关于、简历下载、联系；
2. Hero：AI 应用产品经理定位、一句价值主张、主要 CTA；
3. 证据数字：2 年经验、3 个真实活动、50+ 达人确认记录、周期缩短约 93%、10,439 位达人导入运营库；
4. 三个精选项目：Collab、Creator Hunter / Creator Intel、Airacle 全球化官网；
5. 工作方法：业务抽象、复杂规则、AI 能力产品化、交付与复盘；
6. 简历式经历摘要；
7. 联系 CTA 与简历下载。

### 4.2 Collab 案例页

首屏先展示项目结果与角色，再展开：

- 背景：品牌、运营、创作者间的跨渠道协作不可追踪；
- 限制：小团队、多市场、部分外部数据无法自动回流；
- 关键判断：三方权限、合作状态、名额占用、条件变更、部分履约、争议与人工回填；
- 产品实现：三端架构、核心流程、真实界面截图；
- 结果：3 个活动、50+ 记录、周期中位数约从 1 周到半天；
- 口径：近期小样本观察，非长期全量结论；
- 复盘：状态建模、指标和外部回流应更早前置。

### 4.3 Creator Hunter / Creator Intel 案例页

- 问题：海外达人搜索、核验和整理高度依赖人工；
- 产品流程：需求结构化、候选搜索、条件筛选、匹配排序、推荐理由、人工复核、名单导出；
- AI 边界：模型负责理解与评价，规则校验硬条件，人工决定业务结果；
- 数据：11 个批次、8,905 位去重候选、2 个真实活动、35 个实质回复中 10 个明确报价；
- 边界：8,905 不是触达、注册或激活人数，28.6% 是实质回复至报价率；
- 复盘：外部回复、签约和发布结果尚未形成统一回流闭环。

### 4.4 Airacle 官网案例页

- 目标：建立全球化品牌认知与 B2B 咨询入口；
- 工作：信息架构、中英文内容、4 套视觉探索、选型、8 类页面、AI 辅助开发与上线；
- 关键决策：不使用 AI 虚构或未授权客户案例；
- 结果：完成多语言、SEO、移动端和 3 个品牌域名发布；
- 复盘：工程交付完成，但因缺少埋点、表单和销售归因，暂时不能证明商业成功。

## 5. 视觉与交互

- 风格：编辑式产品作品集，克制科技感，避免常见蓝紫渐变与玻璃卡片堆叠；
- 配色：浅色纸张背景、深灰文字、单一电光蓝或酸性绿高亮；
- 排版：大号标题、强对齐、大留白、结果数字优先；
- 图像：真实产品截图为主，使用浏览器或设备框但不过度装饰；
- 动效：只保留首屏进场、滚动显露、项目卡片微交互与数字反馈；
- 响应式：320px 起可用，主要验收宽度为 390、768、1440px；
- 访问性：语义化 HTML、键盘可用、清晰焦点、合理对比度、减少动效支持。

## 6. 技术方案

继续使用静态 HTML/CSS/JavaScript 和 GitHub Pages，不引入没有必要的框架或后端。首页与案例页采用共享的 CSS 和小型 JavaScript 模块。

预计文件：

- `index.html`；
- `cases/collab.html`；
- `cases/creator-intelligence.html`；
- `cases/airacle-website.html`；
- `styles.css`；
- `script.js`；
- `assets/portfolio/`；
- `resume/zhang-shuhui-ai-product-manager.pdf`；
- `404.html`、`robots.txt`、`sitemap.xml`。

不收集访客信息，联系方式使用 `mailto:`；如后续需要表单和分析，单独立项。

## 7. 错误处理与安全

- 图片缺失时保留可读文字和固定容器，不导致布局塌陷；
- 简历连接必须指向站内可下载 PDF；
- 所有外部链接使用明确标签，新窗口链接添加 `rel="noopener noreferrer"`；
- 项目截图发布前检查邮箱、电话、姓名、报价、客户未授权信息与登录凭证；
- 不在前端包含 API 密钥、内部地址或私有数据。

## 8. 部署与域名

- GitHub Pages 继续使用 `www.zhangshuhui.com` 作为自定义域名；
- 修正根域 `zhangshuhui.com` 的 HTTPS 证书不匹配问题；
- DNS 维持 GitHub Pages 规范的根域 A/AAAA 与 `www` CNAME；
- 启用 Enforce HTTPS，验证根域与 `www` 均无警告访问，并统一重定向至 `www`。

DNS 与 GitHub Pages 后台变更属于外部状态修改，如当前权限无法直接完成，需要输出精确的人工操作步骤。

## 9. 验收标准

### 内容

- 首屏在 30 秒内说清候选人定位、年限、优势与主要结果；
- 三个案例都包含问题、角色、决策、取舍、结果与复盘；
- 所有指标与当前已核验简历口径一致；
- 不存在草稿占位、夸大或未经证实的经历。

### 功能

- 导航、项目跳转、返回首页、简历下载和邮箱联系全部可用；
- 404 页与错误链接无死路；
- JavaScript 禁用时核心内容仍可读；
- 完成链接、资源、HTML 结构、SEO 元数据及简历文件检查。

### 视觉与性能

- 390px、768px、1440px 下无横向溢出、重叠或裁切错误；
- 案例首屏结果与项目图可在一屏内建立理解；
- 首页与案例页视觉一致，但不呈现重复卡片堆叠；
- 图片采用合理尺寸和延迟加载，非首屏截图不阻塞初始渲染；
- 支持 `prefers-reduced-motion`。

## 10. 非目标

- 不伪造个人专利、收入、用户量、客户或 Agent 经验；
- 不建设博客 CMS、登录、后台、评论、聊天机器或不可验证的访客数动画；
- 不为展示技术而引入重型框架；
- 不将个人网站包装成已证明商业转化的产品。
